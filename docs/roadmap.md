# 路线图

> **版本号与发布列车的权威文档是 [`VERSIONING.md`](VERSIONING.md)**，
> 变更记录见 [`CHANGELOG.md`](../CHANGELOG.md)。本文按"里程碑"组织，
> 讲的是每个阶段要验证什么假设，不重复版本号。

原则：**每一步都要能在单机上演示价值**。不做需要"等生态起来才有用"的功能。

---

## M0 —— 可用原型（当前）

已完成：

- [x] 信封协议（act / stage / ttl_hops / budget / 幂等键）
- [x] 注册中心：身份、能力发现、双向好友、群组、三种表决模式、审计
- [x] 服务端强制准入（好友/成员/冒名校验）
- [x] 看门狗：TTL、消息配额、token 预算、simhash 指纹、互推检测、扇出计数、速率
- [x] 出站 DLP（凭据硬阻断 / 内网拓扑与 PII 脱敏 / 密级判定）
- [x] 入站注入检测 + 不可信围栏
- [x] SDK + CLI + 4 个适配器骨架 + 63 个测试
- [x] `doctor` 自检与合规清单

**M0 的完成标准**：一个开发者能在 10 分钟内跑完 `a2alink demo` 并看懂五个机制。
现在达到了。

---

## M1 —— 第一个真实用户

目标：让一个真实的人用它解决一个真实的问题（哪怕只是本机两个 Agent 协作）。

- [ ] 端到端加密：X25519 密钥交换 + AEAD，注册中心降级为盲路由
- [ ] 消息签名：Ed25519，`signature` 字段落地
- [ ] 看门狗状态持久化（防"重启绕过预算"）
- [ ] 全局限额：按 Agent / 按天的成本账户，防"每次新建会话"的慢烧
- [ ] 真模型适配器验证（至少一个：DeepSeek Harness 或 Ollama）
- [ ] `policy.json` 正式化：`deny_terms` / `allow_terms` / `peer_scopes` / 密级映射
- [ ] 人审闸门：超过阈值时挂起，等人点确认（CLI + 简单 TUI）

**退出标准**：有一个外部用户连续用了一周，没有出现"误报烦到关掉闸门"。

---

## M2 —— 团队可用

- [ ] 传输升级：SSE 或 WebSocket（替掉轮询）
- [ ] 多租户：组织隔离、按组织的配额与审计
- [ ] 可观测性：OpenTelemetry trace（`trace_id` 已预留）、指标、消息账本重放
- [ ] 协议弃用机制：字段生命周期，避免信封无限膨胀
- [ ] 介绍人背签（vouching）：解决冷启动与垃圾申请
- [ ] 一致性测试套件（conformance tests），任何第三方实现都要过
- [ ] 部署物：Dockerfile、systemd unit、TLS 反代示例

**退出标准**：能部署在一个 10 人团队的内网里，出问题能靠 trace 定位。

---

## M3 —— 跨组织（需要合规前置）

**前置条件：法务/合规已经明确同意，且公司愿意承担运营方责任。这一阶段不是纯技术决策。**

- [ ] 盲转发中继网关（不解包 payload，不落明文，不存副本）
- [ ] 组织级 CA / 身份联盟
- [ ] 滥用举报与信誉体系（身份成本是公网治理的唯一杠杆）
- [ ] 数据出境策略引擎（按对端所在区域自动降级/阻断）
- [ ] 审计留存与导出（满足取证需求）

---

## 明确不做

- 不做链上身份 / 代币
- 不做 C 端产品
- 不做"自动帮你在公网找人并发送资料"
- 不做实盘/资金动作
- 不承诺 exactly-once

## 想参与？

最有价值的贡献不是加功能，是这三类：

1. **补 DLP 规则**：你在真实场景里漏掉了什么形态？带脱敏后的样例来。
2. **补看门狗模式**：你遇到过哪种本看门狗没覆盖的死循环？
3. **写适配器**：接真框架（CrewAI / 自研 harness），把坑写进文档。

请连同测试用例一起提 PR——没有测试的安全规则，等于没有。
