# v0.3.0 设计稿：本地可视化会话台

> **一句话**：给 `a2alink` 装一个只能在自己电脑上打开的面板，让人**看得见**
> Agent 之间聊了什么、为什么这么发、还剩多少预算、哪条被闸门拦了。
>
> 状态：**设计稿**（v0.3.0 实现）。当前仓库里还没有这个功能，本文是它的规格。

---

## 1. 为什么要有它

现在的痛点是**看不见**。Agent 之间发了什么，只能：
```bash
sqlite3 a2alink.sqlite3 "select envelope from messages order by seq desc limit 5"
```
翻出来是一坨 JSON。于是：

- Agent 循环发消息，人只知道"token 烧完了"，不知道从第几轮开始跑偏；
- 消息被 DLP 拦了，人不知道拦了什么、是不是误杀；
- 想看"我的 Agent 到底跟谁在聊"，得写 SQL。

这不是"锦上添花"，是**可用性的关键缺口**：看不见的系统没法治理。

它同时是一个**调试工具**——接适配器时最常见的抱怨是"我的 Agent 到底发了什么"，
一个面板能省掉一半支持成本。

## 2. 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 多人共享的面板 / 云端面板 | 那就变成一个 Web 服务了：要鉴权、要 TLS、要对公网负责。v0.3 只做本机。 |
| 从面板直接发消息（v0.3 批次） | 只读优先。能写就会有人拿它做"人肉中继"，绕过闸门。写能力放 v0.3.3，且必须走同一套 DLP。 |
| 展示模型原始思维链（raw CoT） | 见 §5，这是本设计里最重要的一个"不做"。 |
| 把面板数据上传/回放 | 面板数据就是内网数据。不出本机。 |

## 3. 形态

一条命令：

```bash
a2alink console            # 默认 127.0.0.1:8788，只读
a2alink console --port 9000
```

打开 `http://127.0.0.1:8788`，三栏布局（单文件 HTML，无构建步骤）：

```
┌──────────────┬────────────────────────────────────┬─────────────────┐
│ 会话列表      │ 消息时间线（当前会话）                │ 状态面板         │
│              │                                    │                 │
│ ● 运维群 (3)  │  ┌─ 14:02:11  我 → research-agent ─┐ │ 看门狗           │
│ ● research-… │  │ task / open  hop=4  1.2k tok     │ │  消息 3/12       │
│ ● sec-agent  │  │ "查一下磁盘告警的常见根因"        │ │  token 1.8k/12k  │
│              │  │ [DLP] 已脱敏 1 处：内网IP         │ │  指纹重复 0      │
│ 待办 (2)      │  └──────────────────────────────────┘ │                 │
│  · 入群邀请   │  ┌─ 14:02:19  research-agent → 我 ─┐ │ 出站闸门          │
│  · 待投票     │  │ result / done  hop=3  0.6k tok   │ │  本次会话命中 2   │
│              │  │ "常见根因有三个…"                 │ │  · 内网IP×1      │
│              │  └──────────────────────────────────┘ │  · 手机号×1      │
│              │  ┌─ 14:02:20  ⚙ 工作笔记 ──────────┐ │                 │
│              │  │ 判定：对方结论缺证据，需要追问    │ │ 扩散保险丝        │
│              │  │ 下一步：发 task，附日志片段       │ │  内容触达 2/4     │
│              │  └──────────────────────────────────┘ │  会话对端 2/6    │
└──────────────┴────────────────────────────────────┴─────────────────┘
```

**"新开一个对话"** 就是左侧列表里点 `+ 新会话`：选择对端（好友/群）、
选择 `act`（task/event/chat）、填一句话。这在 v0.3 里**只是打开一个空的会话视图**
（因为面板只读），v0.3.3 起才允许人和 Agent 一起在里面说话。

## 4. 数据从哪来：本地事件流

面板**不查注册中心**。理由：注册中心可能不在本机、可能已经清库（`purge_old`），
而"我的 Agent 干了什么"这件事应该由我自己留底。

所以引入本地事件流：

```
~/.a2alink/<agent>/events.jsonl      每行一个 JSON，追加写，600 权限
```

事件类型（`kind`）：

| kind | 触发点 | 关键字段 |
|---|---|---|
| `sent` | `send()` 成功后 | `conv, to, act, stage, hop, tokens, dlp_hits[]` |
| `recv` | `recv()` 收到后 | `conv, from, act, stage, ingress_flags[]` |
| `thought` | Agent 主动 `note()` | `conv, step, text, redacted` |
| `guard` | DLP 命中/阻断 | `rule, severity, action, excerpt(已脱敏)` |
| `halt` | 看门狗熔断 | `reason, counts` |
| `admit` | 好友/入群状态变化 | `kind, target, state` |

写入是**同步、追加、失败不影响主流程**（写日志失败不能让发消息失败）。

**统一约束**：所有写入 `events.jsonl` 的文本，**先过 `EgressGuard.check_payload()`**。
事件流本身不能成为新的泄密面——这是整个设计的前置条件。

## 5. "Agent 的思考"怎么展示（本设计最需要克制的地方）

直觉做法是：把模型的 reasoning 内容直接打到面板上。**不这么做**，三个理由：

1. **思维链是新的泄露面。** 出站 DLP 管的是"发出去的消息"，而 CoT 里往往
   包含更多原始上下文（内网路径、客户名、试错的中间结论）。一旦落盘成
   `events.jsonl`，它就是一个**没有经过闸门的历史文件**。
2. **CoT 不可撤销。** 面板最常见的用法是开会投屏和截图。"他脑子里想过这个词"
   和"他说出了这个词"，后果完全不同。
3. **对调试价值反而低。** 排障需要的是"为什么这么发、下一步打算干什么"，
   不是模型的自我辩论过程。

所以定义 `thought` 事件为 **Agent 主动提交的结构化工作笔记**，不是原始 CoT：

```python
me.note("判定：对方结论缺证据",            # 一句结论
        step="ask-for-logs",               # 机器可读的阶段标记
        next="发 task，附日志片段",          # 下一步
        conv=conv_id)
```

规则：
- **三个字段有上限**：结论 ≤ 200 字，下一步 ≤ 200 字；超了截断。
- **同样过 DLP**：命中 critical 的整条丢弃，命中 warn 的脱敏后写入。
- **默认关闭**：`AgentLink(emit_notes=False)`。要用的人自己开，开了才会写盘。
- **不落 payload 原文**：`events.jsonl` 只存摘要与元数据，正文从注册中心的
  `messages` 表按需取（且那个表有 `purge_old`）。

一句话：**面板让人看见"决策"，不让人看见"脑内小抄"。**

## 6. 技术选择（为什么零依赖还能做）

| 需求 | 方案 | 为什么不选替代品 |
|---|---|---|
| HTTP 服务 | `http.server.ThreadingHTTPServer` | 引 Flask/FastAPI 就破坏了"零第三方依赖"这条项目底线 |
| 实时推送 | **SSE**（`text/event-stream`） | WebSocket 要握手升级、要自己写帧解析；SSE 就是长连接的 HTTP 响应，浏览器 `EventSource` 原生支持，断线自动重连 |
| 前端 | 单个 HTML 文件 + 原生 JS + `<template>` | 无构建、无 node_modules、可离线、可直接用 `file://` 打开（只读模式） |
| 状态 | 服务端只维护游标，客户端自己组装 | 面板是只读视图，不需要服务端会话 |

SSE 的推送逻辑：

```python
def stream(self):
    self.send_response(200)
    self.send_header("Content-Type", "text/event-stream")
    self.send_header("Cache-Control", "no-store")
    self.end_headers()
    pos = 0
    while not self.server.stopping:
        for ev in tail(events_path, from_pos=pos):   # 增量读 jsonl
            self.wfile.write(f"data: {json.dumps(ev, ensure_ascii=False)}\n\n".encode())
            self.wfile.flush()
            pos += 1
        time.sleep(0.5)
```

## 7. 安全边界（面板不能变成后门）

| 风险 | 措施 |
|---|---|
| 面板被局域网访问 | **硬编码只允许 `127.0.0.1`**，`--host` 只接受回环地址，传别的值直接报错退出 |
| 面板变成写入口 | v0.3 全部路由只允许 `GET`；`POST` 一律 405 |
| 面板被 CSRF 打 | 只读 + 无 cookie + `SameSite` 不需考虑；启动时生成随机 `token`，页面 URL 必须带 `?k=<token>` |
| 面板泄露正文 | 默认只显示 200 字摘要 + 元数据；"查看全文"需要点一次，且全文同样先过 DLP |
| 事件流被盗 | `events.jsonl` 权限 600，落在 `~/.a2alink/<agent>/` 内（该目录已在 `.gitignore` 中） |
| 面板被截图外传 | 这是人的行为，技术不能管。但**默认不展示 CoT** 已经把风险降了一个量级 |

## 8. 实现里程碑

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M1 | `events.jsonl` 事件流 + `a2alink console` 只读时间线 | 跑 `a2alink demo` 时面板能实时刷出消息 |
| M2 | 三栏布局 + 信封详情 + 看门狗/DLP/保险丝状态 | 一次 DLP 拦截能在面板上看到命中规则与脱敏后的样子 |
| M3 | `thought` 工作笔记流 + `note()` API | 示例 Agent 能在面板上留下可读的决策轨迹 |
| M4 | 待办区可点（同意入群 / 投票） | 在面板上完成一次入群同意，注册中心状态确实变更 |
| M5（0.2.3） | 人来发起消息（走同一套 DLP） | 手发一条含内网 IP 的消息，被拦 |

M1–M3 是 v0.3.0 的范围；M4、M5 放后面，因为**写能力必须比读能力谨慎一个数量级**。

## 9. 与其他版本的关系

- **v0.1.1（已发布）**：`pending_actions()` 已经把"待我表态的邀请 + 待我投的票"
  做成了接口，面板 M4 直接消费它。
- **v0.3.0**：引入端到端加密后，面板显示的是**解密后的本地视图**（密文不出本机），
  设计不变——面板永远是"本机的、明文可见的、只读的"。
- **不做**：任何形式的"远程看别人的 Agent"。那是监控产品，不是这个项目。

## 10. 快速验证（设计是否合理）

如果这个设计是对的，那么 v0.3 发布时应该能一句话说清它的价值：

> 装上一句 `a2alink console`，你就能看见两个 Agent 在你机器上吵架，
> 并且知道它们为什么吵、吵到第几轮该掐断、哪句话被闸门拦了。

如果做不到这句话，说明设计跑偏了。
