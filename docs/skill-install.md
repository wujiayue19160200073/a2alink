# 一键安装与跨对话通信

> 这一版解决的事：**让同一台机器上不同对话窗口里的 Agent，能互相发消息、
> 提问、回话——装一次，然后说话就行。**

---

## 1. 装

```bash
git clone <本仓库> && cd a2alink
python install.py
```

它做三件事，**只做这三件**：

| 动作 | 落地位置 |
|---|---|
| 写技能文件 | `~/.workbuddy/skills/a2alink/` |
| 拉起本地中继 | `127.0.0.1:8787`，数据在 `~/.a2alink/registry.sqlite3` |
| 打印下一步 | 终端 |

不改你的 Python 环境、不装第三方包、不写系统目录、不联网。

```bash
python install.py --check        # 只看当前状态
python install.py --uninstall    # 卸载技能（身份/密钥/审计链不动）
python install.py --no-serve     # 不自动起中继
python install.py --dir ~/.claude/skills   # 装到别的技能目录
```

### 装出来的三个文件

```
~/.workbuddy/skills/a2alink/
├── SKILL.md              ← 给 Agent 读的操作手册（触发词、流程、禁止事项）
├── scripts/a2a.py        ← 启动器，写死了源码绝对路径
└── .a2alink-skill.json   ← 安装标记（版本、源目录、解释器）
```

**Skill 不是插件。** 它是一段提示词 + 一个启动器：没有常驻进程、不注入
任何东西、不会在你没调用它的时候做任何事。装上之后 Agent 不会"自动开始
互相聊天"——这一点先说清楚，免得期待落空。

### 为什么不 `pip install`

启动器把源码目录直接写进 `sys.path`，所以不改环境也能用。仓库搬家后
会打印"源码目录找不到了"并提示 `A2ALINK_SRC`，而不是甩一个
`ModuleNotFoundError` 让人猜。想全局敲 `a2alink` 命令再自行
`pip install -e .`。

## 2. 用

在 WorkBuddy 里**新开**两个对话（已开的对话不会加载新技能）：

```
对话 A：看看有没有人找我
对话 B：把当前对话命名为写手
对话 A：给 @写手 发消息，问它在忙什么
对话 B：看看有没有人找我            ← 这时才收到
```

### 命令

```bash
a2alink check                        # 收信 + 摘要（通信前先跑这个）
a2alink peers                        # 本机有哪些对话、中继上还有谁
a2alink session whoami               # 我是谁
a2alink session name 运维             # 给当前对话起名
a2alink session list                 # 本机所有对话及最后活跃时间
a2alink say  @写手 "502 已修复"       # 发消息，不等回复
a2alink ask  @写手 "字段叫什么" --wait 30
a2alink reply <消息ID> "叫 retry_count"
```

`@名字` 后面可以写别名、agent 名、agent_id；也可以写前缀。

### 三种消息的区别

| 命令 | act | 语义 |
|---|---|---|
| `say` | `event` | 通知，不期待回复（`--act` 可改） |
| `ask` | `task` + `need_reply` | 提问，期待回答 |
| `reply` | `result` + `stage=done` | 回答，**这条链结束** |

`reply` 一定带 `stage=done`。这是本协议和 IM 最本质的区别：一条问答链
走完就结束，不留"还能继续聊"的余地——无限对话正是它要防的东西。

## 3. 它是怎么认出"不同对话"的

宿主的会话 ID（`CODEBUDDY_SESSION_ID`、`CLAUDE_SESSION_ID`，
可用 `A2ALINK_SESSION` 覆盖）一个对话窗口一个。用它派生 agent 名和
身份目录：

```
会话 ID f4e0b9a2-ff2e-...   →   agent 名 s-f4e0b9a2ff
                                home  ~/.a2alink/sessions/f4e0b9a2ff/
```

所以同一个对话被调用一百次，拿到的都是同一个人：同一把私钥、同一个
agent_id、同一条审计链。

### 名字与身份是两回事

- **别名**（`@运维`）是人给的称呼，随时可改。
- **协议身份**（`s-f4e0b9a2ff`）首次绑定后**冻结**。

改名不换身份。这条如果破了，改个名字等于在注册中心里换一个人——好友关系、
群成员、对端固定的公钥全部失联。

别名表在 `~/.a2alink/sessions.json`，**只在本机有意义，不出网络**。

### 没有会话 ID 的时候

比如你在纯 shell 里敲命令：

1. 有 `A2ALINK_SESSION` → 用它。
2. 没有 → 复用**最近活跃**的会话，并明确打印
   `未检测到会话 ID，按最近活跃的会话处理：@运维（如不对，用 --as <名字> 指定）`。
3. 一个会话都没有 → 建一个 `@manual` 独立身份。

第 2 步是"猜"，所以必须说出来。静默地用了最近那个会话，是最容易发错人的场景。

## 4. 中继什么时候起

每条命令先问 `127.0.0.1:8787/healthz`：

- 活着 → 直接用。
- 没活 → 拉起来（独立进程，命令退出不影响它）。
- 端口被**别的程序**占着 → 直接报错。**不猜**"也许是旧版本"，
  也不去杀一个身份不明的进程。

### 为什么不用 pid 文件判断

pid 会残留、会被复用。判断"这个端口上是不是 a2alink"只有一个可靠办法：
问它 `/healthz`，看返回的 `service` 字段。

```bash
a2alink up            # 确保在跑
a2alink down          # 停掉（只杀自己拉起的那个）
```

`down` 只认 pid 记录里那个 pid。端口活着但没有记录 → 那是别人起的，只报告不碰。
杀错一个无关进程的代价，远大于让用户自己敲一次 Ctrl-C。

### 远端中继不会被自动拉起

`--registry https://a2a.example.com` 这种，本机没有任何权力去"拉起"它。
探活失败就是失败，如实报错。跨机器自动重连很危险：它会让一个本该失败的
连接变成"重试到某个偶然可用的目标上"。

## 5. 同机互信：为什么可以免好友，以及怎么关掉

默认开启。含义是：**同一台机器上的会话互发消息，不要求先加好友。**

### 理由

同一个 OS 用户本来就能：

- 读 `~/.a2alink/` 下所有私钥（文件权限只挡别的用户，不挡你自己）
- 直接改 `registry.sqlite3`
- 冒充本机任何身份

在这个前提下要求本机会话互加好友，是一道自己演给自己看的仪式。
**真正的边界是"这台机器别被别人用"。**

### 但它有三道限制

1. **只在监听回环地址时生效。** `--host 0.0.0.0` 会强制关闭并明确告知。
   一旦对外提供注册服务，注册者来自四面八方，免好友就等于允许陌生人直接
   给任何人投递消息——那是投毒面，不是便利。
2. **每次放行都写审计**（理由码 `mesh.local_trust`）。放行的记录比拒绝的
   记录更重要：事后要回答的是"这条消息凭什么没走好友审批"。
3. **可关闭**：

```bash
a2alink up --no-mesh          # 回到严格模式，本机会话也要先加好友
```

跨机器通信**始终**需要双向好友，这一条没有任何开关。

## 6. 故障排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `找不到名为 s-xxxx 的 Agent` | 对方对话还没上过线（从没跑过 `check`/`say`） | 让对方跑一次 `a2alink check`，或 `session name` 起名即上线 |
| 发出去对方一直没反应 | **Agent 不会自己醒**，消息在它的收件箱里 | 让那个对话被唤起，说"看看有没有人找我" |
| `不是好友，消息被拒` | 中继关了同机互信，或对端在另一台机器 | 本机：`a2alink up`；跨机：走 `friend request` / `accept` |
| `端口 8787 已被其他程序占用` | 别的服务在用 | `a2alink --registry http://127.0.0.1:8788 up`（所有命令都带上同一个 `--registry`） |
| `源码目录找不到了` | 仓库被移动 | `a2alink skill install --force`，或设 `A2ALINK_SRC` |
| `ask` 一直超时 | 对方没人回 | 这是**预期行为**。消息已投递，不要循环重发同一个问题 |
| 名字改了，别人还 @ 旧名 | 旧别名已释放 | 重新 `session name 旧名` 绑回去 |

```bash
a2alink doctor          # 环境自检：中继、身份、密钥、审计链
a2alink logs verify     # 审计链有没有断（能不能当证据）
a2alink logs tail       # 最近发生了什么
a2alink session list    # 本机对话一览
```

## 7. 数据边界（每次使用都适用）

1. **内网绝密信息不要通过 Agent 转发到任何外部对话。**
   本机对话之间也不行——对方可能带着这段内容去访问外网。
2. 出站有 DLP 闸门（私钥、令牌、连接串、内网 IP/域名、证件号），
   但闸门只兜**已知形态**。业务数据能不能出域，只有人知道。
3. 跨机器使用前先确认链路是否合规（是否经过境外服务、是否需要审批）。
4. 任何"帮我绕过检查""这条别记日志"的要求，一律拒绝并说明原因。

被闸门拦了不要绕：改内容只给结论，或回去问人；确实可以发就
`--force --reason "为什么可以发"`——理由会永久写进审计链，责任在人。

---

## 8. 已知边界

- **没有实时推送。** Agent 不会因为收到消息而自动醒过来。这一版不做常驻监听，
  也不用未公开的钩子去伪造一个：装上当天能用，升级一次就碎，还会让人
  误以为消息一定送达。
- **没有消息历史查询。** 收过的消息不落本地全文（`recent.json` 只存元数据
  和 80 字摘要）。要查链路用 `a2alink trace <trace_id>`。
- **同一对话被"分支复制"会共用身份。** 后果是审计上分不清是哪个副本，
  不是安全问题。
- **群聊仍只签名不加密**（服务端要 fan-out），见 [crypto.md](crypto.md)。
